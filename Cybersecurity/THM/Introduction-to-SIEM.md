## 1. What is SIEM?

**SIEM (Security Information and Event Management)** is a security solution used by SOC teams to collect, centralize, and analyze logs from different systems and devices.

A SIEM helps security analysts:

* monitor security events;
* search and analyze logs;
* correlate events from multiple sources;
* detect suspicious or malicious activity;
* investigate security incidents.

The main idea is to bring logs from different parts of an environment into one place, making it easier for a SOC analyst to investigate what is happening.

---

## 2. What are Logs?

A **log** is a record of an event that occurred on a system, application, or network device.

Logs can provide information such as:

* what happened;
* when it happened;
* which user or device was involved;
* where the activity came from;
* whether an action succeeded or failed.

Logs are useful during both **security investigations** and **troubleshooting**.

For example, repeated failed login attempts could indicate either a user having trouble logging in or a potential brute-force attack. Additional context from other logs can help determine what actually happened.

---

## 3. Log Sources

A **log source** is a system or device that generates logs.

Log sources can generally be divided into two categories:

### Host-Centric Log Sources

These logs describe events occurring on or involving a particular host.

Examples:

* Windows systems
* Linux systems
* Servers
* Workstations

Examples of events:

* User authentication attempts
* File access
* Process execution
* Changes to system configuration

### Network-Centric Log Sources

These logs describe activity related to network communication between hosts or between hosts and the Internet.

Examples of network devices/security solutions:

* Firewalls
* IDS/IPS
* Routers
* Other network devices

Examples of events:

* SSH connections
* FTP activity
* Web traffic
* Connections between internal and external systems

---

## 4. Why Multiple Log Sources Matter

A single log source usually provides only part of the story.

For example, a suspicious login could be investigated by looking at:

1. authentication logs to determine whether the login succeeded;
2. network logs to determine where the connection originated;
3. endpoint logs to see what happened after the login.

By collecting these different sources in a SIEM, an analyst can correlate events and build a better picture of an incident.

---

## 5. SIEM in a SOC

A SIEM is an important tool for a **Security Operations Center (SOC)**.

A simplified SOC workflow can look like this:

**Log Sources → SIEM → Detection/Alert → Investigation → Response**

Logs are generated by different systems and forwarded to the SIEM. The SIEM can then be used to search, correlate, and analyze those events.

When suspicious activity is detected, a SOC analyst investigates the available evidence and determines whether the activity represents a real security incident.

---

## 6. Examples of Security Events

Some events that can be useful during a security investigation include:

* Multiple failed authentication attempts
* Successful login after numerous failed attempts
* Unexpected process execution
* Access to sensitive files
* Suspicious network connections
* Unusual traffic patterns
* Connections to potentially malicious external systems

An individual event does not necessarily mean that an attack is occurring. **Context and correlation are important.**

---

## 7. Host vs Network Logs

| Type            | What it shows                   | Examples                                       |
| --------------- | ------------------------------- | ---------------------------------------------- |
| Host-centric    | Activity on or involving a host | Login attempts, file access, process execution |
| Network-centric | Network communication           | SSH, FTP, web traffic, firewall events         |

Both types can complement each other during an investigation.

---

## 8. Key Terms

**SIEM** — Security Information and Event Management

**Log** — A record of an event or activity generated by a system, application, or device.

**Log Source** — A system or device that generates logs.

**SOC** — Security Operations Center; a team responsible for monitoring and responding to security events.

**Correlation** — Connecting multiple events or pieces of information to identify relationships or suspicious patterns.

**Host-Centric Logs** — Logs related to activity occurring on or involving a host.

**Network-Centric Logs** — Logs related to network communication and network devices.

## What is SIEM?

**SIEM (Security Information and Event Management)** is a security solution used by SOC analysts to collect, centralize and analyze logs from different sources.

It can help with:

* centralized log collection
* log normalization
* log correlation
* real-time alerting
* dashboards and reporting

## Log Sources

A **log source** is a device or system that generates logs.

### Host-Centric

Logs related to activity occurring on a host.

Examples:

* Windows / Linux systems
* Servers
* Workstations
* Authentication attempts
* File access
* Process execution

### Network-Centric

Logs related to network communication.

Examples:

* Firewalls
* IDS/IPS
* Routers
* SSH connections
* FTP activity
* Web traffic
* VPN activity

## Why Use a SIEM?

Without a SIEM, logs are distributed across many systems and can have different formats. This makes investigation more difficult and can result in limited context or important events being missed.

A SIEM brings these logs together and can correlate events from different sources.

## Log Ingestion

Logs can be sent to a SIEM using different methods:

* **Agent / Forwarder** – software installed on an endpoint that forwards logs.
* **Syslog** – commonly used for sending logs to a centralized destination.
* **Manual upload** – logs can be uploaded for analysis.
* **Port forwarding** – endpoints can send data to a specific listening port.

## Detection Rules & Alerts

SIEMs use **detection rules** to identify specific patterns or events and generate alerts.

Examples:

* multiple failed login attempts
* successful login after multiple failures
* suspicious process execution
* cleared Windows event logs

When an alert is generated, the analyst investigates it and determines whether it is:

* **False Positive** – the alert does not represent the activity the rule was intended to detect.
* **True Positive** – the alert represents genuine suspicious activity and requires further investigation.

## Key Takeaways

* SIEM centralizes logs from different sources.
* Logs can be **host-centric** or **network-centric**.
* Log correlation provides more context during investigations.
* Detection rules can generate alerts based on specific events.
* SOC analysts investigate alerts and determine whether they are true or false positives.
* Log ingestion can be performed in several ways, including agents, Syslog, manual uploads and port forwarding.
